# การออกแบบระบบแจ้งเตือน TCPR

ฉบับภาษาไทยของ `2026-09-30-notifications-design.md` เนื้อหาตรงกัน ถ้าสองฉบับขัดกัน ให้ยึดฉบับภาษาอังกฤษ

แจ้งเตือนในแอปพร้อมอีเมล สำหรับใบงานใหม่ที่เข้าคิว การเปลี่ยนสถานะ และการเลยกำหนดเสร็จหนึ่งครั้ง แอดมินตั้งได้ตามบทบาทว่าเหตุการณ์ใดให้กระดิ่ง และเหตุการณ์ใดให้อีเมลด้วย การเตือนใกล้ครบกำหนด (เหลือ 4 ชั่วโมง), PM, คลังอะไหล่ และเช็กลิสต์/ลายเซ็น อยู่นอกขอบเขตรอบนี้

## ปัญหา

ช่างรู้ว่ามีงานใหม่ได้ทางเดียวคือเปิด `/queue` ผู้แจ้งรู้ว่างานถูกรับ ส่งตรวจ หรือถูกส่งกลับ ได้ทางเดียวคือเปิดใบงาน งานที่เลยกำหนดผู้จัดการเห็นได้ใน `/ops` แต่คนรับงาน (หรือช่างทั้งสาย ถ้ายังไม่มีใครรับ) ไม่ได้รับแจ้งเมื่อเลย `dueAt`

## ช่องทาง

ทุกการแจ้งเตือนบันทึกในแอปก่อน กระดิ่งบนแถบเมนูและหน้า `/notifications` คือข้อมูลหลัก

อีเมลเป็นสำเนาของแถวที่มีอยู่แล้ว ส่งเมื่อครบทั้งสามข้อนี้: สวิตช์กระดิ่งของบทบาทนั้นสำหรับเหตุการณ์นั้นเปิดอยู่ สวิตช์อีเมลของบทบาทนั้นเปิดอยู่ และผู้รับมี `User.email` ข้อความเป็นภาษาไทย ระบุเลขใบงาน และลิงก์ไป `{APP_URL}/tickets/{id}`

ผู้รับแต่ละคนได้อีเมลของตัวเอง ช่าง 5 คนที่มีอีเมลจะได้ 5 ฉบับ

ถ้ายังไม่ได้ตั้งค่า SMTP ผู้รับไม่มีอีเมล สวิตช์อีเมลปิด หรือส่งไม่สำเร็จ การเปลี่ยนใบงานและแถวแจ้งเตือนในแอปยังคงอยู่ ไม่ส่งอีเมลซ้ำอัตโนมัติเมื่อส่งไม่สำเร็จ

## ค่าที่แอดมินตั้ง

เปิดหน้า `/admin/notifications` ได้เฉพาะ `ADMIN` หน้านี้เป็นตาราง แถวคือเหตุการณ์ `CREATED`, `CLAIMED`, `COMPLETED`, `REJECTED`, `ACCEPTED`, `OVERDUE` คอลัมน์คือแปดบทบาท `REQUESTER`, `SECTION_MANAGER`, `EM_MANAGER`, `EM_TECHNICIAN`, `IT_MANAGER`, `IT_TECHNICIAN`, `GM`, `ADMIN`

แต่ละช่องมีสองสวิตช์ คือกระดิ่งในแอป กับอีเมล บันทึกสวิตช์อีเมลเป็นเปิดได้เมื่อสวิตช์กระดิ่งในช่องเดียวกันเปิดอยู่ ปิดกระดิ่งแล้วระบบเก็บสวิตช์อีเมลเป็นปิดด้วย

แถวค่าที่ไม่มีในตารางแปลว่าทั้งสองสวิตช์ปิด การ seed เขียนช่องที่เปิดเป็นค่าเริ่มต้นด้านล่าง เพื่อให้ติดตั้งใหม่ตรงกับตารางนี้ การเปลี่ยนสวิตช์มีผลกับการแจ้งเตือนที่เกิดหลังจากนี้ แถวที่บันทึกไปแล้วไม่ถูกแก้

ค่าเริ่มต้นที่ทั้งกระดิ่งและอีเมลเปิด:

| เหตุการณ์ | บทบาท |
|---|---|
| `CREATED` | `EM_TECHNICIAN`, `IT_TECHNICIAN` |
| `CLAIMED`, `COMPLETED`, `REJECTED` | `REQUESTER` |
| `ACCEPTED` | ไม่มีใคร |
| `OVERDUE` | `EM_TECHNICIAN`, `IT_TECHNICIAN` |

ช่องอื่นปิดเป็นค่าเริ่มต้น แอดมินเปิดเพิ่มได้ รวมถึง `ACCEPTED` และบทบาทผู้จัดการสำหรับใบงานใหม่หรืองานเลยกำหนด

## ใครได้รับเมื่อช่องนั้นเปิด

เฉพาะผู้ใช้ที่ยังใช้งานอยู่ คนที่เพิ่งกดทำรายการนั้นถูกตัดออกจากผู้รับของรายการนั้น ข้อนี้ไม่ใช่สวิตช์

เมื่อกระดิ่งของบทบาทนั้นเปิดสำหรับเหตุการณ์ คนที่เข้าเงื่อนไขคือ

| บทบาท | คนที่ได้รับ |
|---|---|
| `REQUESTER` | ผู้แจ้งของใบงานนั้น |
| `SECTION_MANAGER` | ผู้จัดการแผนกที่ใช้งานอยู่และแผนกตรงกับแผนกของผู้แจ้ง ไม่มีใครได้ ถ้าผู้แจ้งไม่มีแผนก |
| `EM_MANAGER`, `EM_TECHNICIAN` | ผู้ใช้ที่ใช้งานอยู่และมีบทบาทนั้น เฉพาะใบงานประเภท `MACHINE`, `ELECTRIC`, `STAFF` |
| `IT_MANAGER`, `IT_TECHNICIAN` | ผู้ใช้ที่ใช้งานอยู่และมีบทบาทนั้น เฉพาะใบงานประเภท `IT` |
| `GM`, `ADMIN` | ผู้ใช้ที่ใช้งานอยู่และมีบทบาทนั้น ทุกประเภทใบงาน |

`OVERDUE` มีข้อจำกัดเพิ่มสำหรับสองบทบาทช่าง ถ้ามี `assigneeId` บทบาทช่างแจ้งเฉพาะคนรับงาน และเฉพาะเมื่อคนรับงานยังใช้งานอยู่และบทบาทของคนรับงานเปิดกระดิ่ง `OVERDUE` ช่างคนอื่นในสายไม่ถูกเพิ่ม คนรับงานที่ปิดการใช้งานแล้วไม่สร้างแถวเลยกำหนดของช่าง บทบาทที่ไม่ใช่ช่างยังได้รับเลยกำหนดตามตารางด้านบน เมื่อกระดิ่ง `OVERDUE` ของบทบาทนั้นเปิดอยู่

`CREATED` ของ `REQUESTER` แจ้งผู้แจ้งได้เมื่อมีคนอื่นเป็นคนสร้างใบงาน คนสร้างถูกตัดออกตามกฎคนกด

## เหตุการณ์

ผู้รับแต่ละคนมีแถวของตัวเอง คนหนึ่งกดอ่านแล้วไม่กระทบคนอื่น

| เหตุการณ์ | เมื่อไร |
|---|---|
| `CREATED` | สร้างใบงานเข้าคิว |
| `CLAIMED` | `CLAIM` สำเร็จ |
| `COMPLETED` | `COMPLETE` สำเร็จ ช่างส่งงาน ตั้ง `closedAt` และสถานะเป็นรอตรวจรับ |
| `REJECTED` | `REJECT` สำเร็จ ส่งใบงานกลับไปให้ช่างและล้าง `closedAt` |
| `ACCEPTED` | `ACCEPT` สำเร็จ ผู้แจ้งปิดงาน ผู้รับค่าเริ่มต้นคือไม่มีใคร |
| `OVERDUE` | ตัวสแกนเจอใบงานที่ยังเปิดและเลย `dueAt` |

การแจ้งสถานะเกิดทุกครั้งที่ทำรายการสำเร็จ ถ้า `CLAIM` ใหม่หลัง `REJECT` จะแจ้งอีกครั้ง โดยใช้ค่าสวิตช์ที่เป็นอยู่ในตอนนั้น

งานเลยกำหนดแจ้งครั้งเดียวต่อใบงาน ต่อผู้รับ และต่อเวลา `dueAt` นั้นพอดี

- ถ้าปิดใบงาน หรือเปลี่ยน `dueAt` ก่อนตัวสแกนเห็นว่าเลยกำหนด กำหนดเดิมนั้นไม่แจ้ง
- ถ้าผู้จัดการตั้ง `dueAt` ใหม่ เวลาใหม่นั้นแจ้งได้หนึ่งครั้งเมื่อเลยกำหนด
- ผู้รับที่มีแถวเลยกำหนดสำหรับ `dueAt` นี้อยู่แล้วจะไม่ถูกแจ้งซ้ำ การรับงานทีหลังจึงไม่ส่งเลยกำหนดครั้งที่สองให้คนเหล่านั้น
- ผู้รับที่ยังไม่มีแถวเลยกำหนดสำหรับ `dueAt` นี้ ยังได้รับได้ในรอบสแกนถัดไป รวมถึงบทบาทที่แอดมินเปิดทีหลังรอบแรก ตราบใดที่ใบงานยังเปิดและยังเลยกำหนดนั้น

ไม่มีการแจ้งเตือนเมื่อเหลือเวลา 4 ชั่วโมงหรือน้อยกว่า (`at_risk`)

## กระดิ่งในแอป

แถบเมนูแสดงกระดิ่งพร้อมจำนวนที่ยังไม่อ่านของผู้ใช้ที่ล็อกอิน กดกระดิ่งไปหน้า `/notifications`

แต่ละแถวแสดงข้อความภาษาไทยสั้นๆ เวลา และลิงก์ไปใบงาน กดลิงก์แล้วแถวนั้นถือว่าอ่านแล้ว ในหน้ามีปุ่มอ่านทั้งหมดของผู้ใช้ปัจจุบัน แถวเก่ายังอยู่ในหน้า ไม่มีอะไรทับหน้าใบงาน

ผู้ใช้เห็นได้เฉพาะแถวของตัวเอง ใส่ id ของคนอื่นใน URL ก็ไม่เห็นแถวของคนนั้น

ข้อความ:

- `CREATED`: `มีใบงานใหม่ {ticketNo}`
- `CLAIMED`: `{ticketNo} ถูกรับงานแล้ว`
- `COMPLETED`: `{ticketNo} รอตรวจรับ`
- `REJECTED`: `{ticketNo} ถูกส่งกลับให้แก้ไข`
- `ACCEPTED`: `{ticketNo} ตรวจรับแล้ว`
- `OVERDUE`: `{ticketNo} เลยกำหนดเสร็จ`

## บันทึกแถวเมื่อไร

การสร้าง รับงาน ส่งตรวจ ส่งกลับ และตรวจรับ บันทึกแถวแจ้งเตือนใน server action เดียวกับการบันทึกใบงาน ให้ผู้รับทุกคนที่ตารางค่าเลือกไว้ ถ้า action นั้นล้มเหลว จะไม่เหลือแถวแจ้งเตือน การตรวจรับบันทึกแถวเฉพาะเมื่อมีอย่างน้อยหนึ่งบทบาทเปิดกระดิ่ง `ACCEPTED`

แถวเลยกำหนดบันทึกโดยตัวสแกนเท่านั้น action ของใบงานไม่สแกนหางานเลยกำหนด

## ตัวสแกนงานเลยกำหนด

ตัวสแกนเลือกใบงานที่ `closedAt` เป็นค่าว่าง `dueAt` ไม่ว่าง `dueAt` อยู่ก่อนเวลาปัจจุบัน และมีผู้รับที่ถูกเลือกอย่างน้อยหนึ่งคนที่ยังไม่มีแจ้งเลยกำหนดสำหรับใบงานนั้นกับ `dueAt` นั้น

ตัวสแกนเป็นคำสั่งในเครื่อง `npm run notifications:scan` อ่าน `NOTIFY_CRON_SECRET` จาก environment และจบโดยไม่บันทึกแถวเมื่อไม่มี secret ไม่ใช่ URL สาธารณะที่เรียกได้โดยไม่ยืนยันตัวตน บนเครื่องนี้ Windows Task Scheduler รันคำสั่งนั้นอย่างน้อยทุกหนึ่งนาที โปรเซส Next.js ไม่ตั้งตัวจับเวลาเอง

## อีเมล

ค่าตั้ง SMTP คือ `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS` และ `MAIL_FROM` ถ้าไม่มีค่าเหล่านี้ ระบบเก็บแถวในแอปไว้และข้ามอีเมล

ข้อความเป็นภาษาไทย ระบุเลขใบงาน บอกเรื่องเดียวกับข้อความในแอป และลิงก์ไป `{APP_URL}/tickets/{id}`

ส่งอีเมลหลังบันทึกแถวแจ้งเตือนสำเร็จแล้วเท่านั้น และส่งเฉพาะผู้รับที่บทบาทเปิดสวิตช์อีเมลสำหรับเหตุการณ์นั้น การเรียก SMTP ที่ช้าหรือล้มเหลวต้องไม่อยู่ใน transaction ของใบงาน

## ข้อมูล

`NotificationPreference` เก็บหนึ่งแถวต่อบทบาทต่อเหตุการณ์

- id บทบาท
- ประเภท: `CREATED`, `CLAIMED`, `COMPLETED`, `REJECTED`, `ACCEPTED`, `OVERDUE`
- ค่ากระดิ่งในแอป
- ค่าอีเมล

ความไม่ซ้ำคือ `(roleId, kind)`

`Notification` เก็บ

- id ผู้รับ
- id ใบงาน
- ประเภท หกค่าเดียวกับด้านบน
- สำเนา `dueAt` บังคับสำหรับ `OVERDUE` และเป็นค่าว่างสำหรับประเภทอื่น
- เวลาสร้าง
- เวลาอ่าน เป็นค่าว่างจนกว่าจะอ่าน
- เวลาส่งอีเมล (ไม่บังคับ) และข้อความผิดพลาดของอีเมล (ไม่บังคับ)

ความไม่ซ้ำของเลยกำหนดคือ `(ticketId, dueAt, recipientId, kind=OVERDUE)` แถวสร้างใบงานและแถวสถานะไม่บังคับไม่ซ้ำตลอดอายุใบงาน เพราะรายการเดิมเกิดซ้ำได้หลังส่งกลับ

## การจัดการข้อผิดพลาด

- action ของใบงานล้มเหลว: ไม่มีแจ้งเตือนสำหรับครั้งนั้น
- สวิตช์กระดิ่งปิดสำหรับทุกบทบาทที่เข้าเงื่อนไข: ไม่มีแถว
- ผู้รับปิดการใช้งาน: ไม่มีแถว
- สวิตช์อีเมลปิด หรือผู้รับไม่มีอีเมล: เก็บแถวในแอป ข้ามอีเมล
- ไม่ได้ตั้ง SMTP หรือส่งแล้วเกิดข้อผิดพลาด: ใบงานและแถวในแอปยังคงอยู่ เก็บข้อความผิดพลาดของอีเมล ไม่ส่งซ้ำ
- ไม่มี secret ของตัวสแกน: จบก่อนอ่านใบงาน
- ใบงานเก่าที่ `dueAt` เป็นค่าว่าง: ตัวสแกนข้าม
- คนที่ไม่ใช่แอดมินเปิด `/admin/notifications` ถูกส่งออกเหมือนหน้าแอดมินหน้าอื่น

## นอกขอบเขต

การเตือนใกล้ครบกำหนด การเตือนเลยกำหนดซ้ำ หน้าตั้งค่าแจ้งเตือนรายคน LINE SMS อีเมลสรุปรวม การส่งอีเมลซ้ำอัตโนมัติ push notification และคิวงานแยก (worker)

## การทดสอบ

เทสต์ฟังก์ชันล้วนครอบคลุมการเลือกผู้รับด้วยตารางค่าเริ่มต้น: สาย EM กับ IT, ตัดผู้ใช้ที่ปิดการใช้งาน, ตัดคนกด, แจ้งผู้แจ้งเมื่อรับงาน ส่งตรวจ และส่งกลับ, ไม่แจ้งใครเมื่อตรวจรับ, เลยกำหนดของบทบาทช่างแจ้งคนรับงานอย่างเดียว, เลยกำหนดที่ยังไม่มีคนรับแจ้งช่างทั้งสาย และไม่แจ้งเลยกำหนดซ้ำให้ผู้รับที่มีแถวของ `dueAt` นั้นแล้ว

เทสต์ค่าที่แอดมินตั้งครอบคลุมการปิดอีเมลของช่างแล้วใบงานใหม่ยังบันทึกแถวในแอปและไม่ส่งเมล, การเปิด `CREATED` ให้ `EM_MANAGER` แล้วผู้จัดการ EM ถูกเพิ่มในใบงานสาย EM, การเปิด `ACCEPTED` ให้ `EM_TECHNICIAN` แล้วช่างได้รับแจ้ง, และผู้จัดการแผนกได้รับเฉพาะใบงานของแผนกตัวเอง

เทสต์ action ยืนยันว่าสร้างใบงานแล้วบันทึกแถวให้ช่าง และสร้างไม่สำเร็จไม่บันทึกแถว

เทสต์ตัวสแกนยืนยันว่าใบงานที่ปิดแล้วและ `dueAt` ที่ยังไม่ถึงไม่สร้างอะไร, เลย `dueAt` บันทึกครั้งเดียว, เปลี่ยน `dueAt` แล้วบันทึกได้อีกหนึ่งครั้ง, และบทบาทที่เปิดหลังรอบเลยกำหนดครั้งแรกได้รับแถวในรอบถัดไปตราบใดที่กำหนดนั้นยังเปิดอยู่

เทสต์อีเมลยืนยันว่าไม่มีที่อยู่ สวิตช์อีเมลปิด หรือไม่ได้ตั้ง SMTP จะข้ามการส่งโดยไม่ลบแถว และส่งแล้วเกิดข้อผิดพลาดจะเก็บข้อความผิดพลาดและแถวยังอยู่

## ถือว่าเสร็จเมื่อ

ช่างเห็นตัวเลขบนกระดิ่งเมื่อมีใบงานใหม่ในสายของตัวเอง และเปิดใบงานจาก `/notifications` ได้ ผู้แจ้งได้รับแจ้งเมื่อรับงาน ส่งตรวจ และส่งกลับ และไม่ได้รับแจ้งเมื่อตัวเองตรวจรับ ตามตารางค่าเริ่มต้น ใบงานที่ยังเปิดแจ้งหนึ่งครั้งเมื่อเลย `dueAt`: คนรับงานถ้ามี ไม่อย่างนั้นแจ้งช่างของสาย และบวกบทบาทอื่นที่แอดมินเปิดไว้ แอดมินปิดอีเมลของบทบาทที่ยังได้กระดิ่งได้ และเปิดกระดิ่งให้บทบาทที่ตารางค่าเริ่มต้นข้ามได้ อีเมลส่งเมื่อสวิตช์นั้นเปิด ผู้ใช้มีที่อยู่ และตั้ง SMTP แล้ว อีเมลส่งไม่สำเร็จ แจ้งเตือนในแอปยังอยู่
